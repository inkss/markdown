# 工作区初始化模板

> **版本**：v1.0（2026-07-27）
> **用途**：作为初始化清单，在新工作区快速搭建一套通用的工作区管理结构。
> **用法**：本文分两层——§0–§5 是**规则全集与设计依据**（理念、铁律、结构、流程，供建立完整理解）；§6 是从中提取的**可直接落地文件子集**，把其中每个代码块分别存为同名文件即完成基础搭建。
> **自包含**：§6 生成的治理文件完全自包含，不引用、不提及本模板；拿到后可直接使用。
> **用后处理**：把 §6 文件落地（导入）完成后，本模板文件本身可按目标工作区的规则处理（移入归档域或删除），生成的治理文件不依赖它。

---

## 0. 设计理念（核心五原则）

1. **通用容器**：一个工作区承载不同主题的任务，不绑定单一项目；目录路径与命名未来可调。
2. **路径无关 / 命名无关**：规则刻意不依赖任何固定目录名或绝对路径，重命名/挪动域目录不影响规则生效。
3. **域规则隔离**：每个主题域自带 `README.md` 承载本域强制规则；处理某主题时**只遵守该域规则**，其他域规则不生效。
4. **轻量导航**：`PROJECT_INDEX.md` 只做地图（有哪些域、状态、关键文件），不重复各域详细规则。
5. **分类归并（两层）**：相似主题域归入同一分类目录，形成「分类 → 主题域」两层；根目录只保留治理三件套 + 分类目录，不堆平级域。**分类层不承载强制规则**，域级规则仍只在域 `README.md`（沿用「域规则隔离」）。

---

## 1. 通用操作铁律（跨域生效，与工作区组织无关）

以下约束**不绑定任何主题域**，在任何任务、任何域都生效；它们独立于「组织结构」，是 AI 行为的硬边界，且**不依赖 Git**。

- **系统级计划任务须逐次单独授权**：在外部系统创建 cron / systemd / 计划任务（或等效定时机制）**非绝对禁止，但每次执行前须再次明确确认授权**——即便同一轮已获整体授权（如「全部授权」「你看着办」），遇到此类操作仍须单独再问。**授权不继承、不泛化**。
- **远程设备先读域 README**：触碰 NAS / 服务器 / 路由器等远程设备前，必须先读该设备对应域 `README.md` 的强制规则并遵守，未读不操作。
- **脚本 / 配置换行统一 LF**：面向 Linux / 远程的脚本与配置文件一律 **LF 换行、禁 CRLF**（Windows 编辑器保存时显式选 UTF-8 LF），避免跨平台脚本因 CRLF 解析失败。
- **密钥 / 凭证红线**：任何含密钥、token、密码、私人配置的文件**绝不写入仓库或记忆文件**；如必须提及，只记「位置 + 用途」，不记明文。
- **规则只写硬约束**：记忆与文档中只记录「禁止什么 / 必须什么」，不写「为什么这么定」的事故背景与来龙去脉。

## 2. 根目录治理文件（三件套）

根目录只放治理文件 + 分类目录，不在根目录散落产出物。

```
AGENTS.md          # 操作守则（全局工作流，每次会话必读）
README.md          # 结构总览（本文件或简化版）
PROJECT_INDEX.md   # 分类与主题域地图（轻量索引，活文档）
```

其余皆为**分类目录**，其下是主题域目录（分类不承载域强制规则）。

## 3. 分类 / 主题域划分逻辑

- **两层结构**：分类（顶层目录，按作用域归类，如 `infra/` `net/` `personal/` `meta/`）→ 主题域（分类下子目录，一个主题域 = 一个子目录，自带 `README.md`）。
- **分类示例**：`infra/web-server/`（自托管站点）`net/proxy/`（网络）`personal/resume/`（个人文档）`meta/maintenance/`（工作区元），按需替换。
- **分类目录可带薄 `README.md`**（仅分类级范围说明），**不承载**域强制规则；域强制规则只在主题域 `README.md`。
- **新增域流程**：归入某分类 → 建主题域子目录 → 写 `README.md`（用途 + 关键文件 + 强制规则 + 状态）→ 在 `PROJECT_INDEX.md` 对应分类下登记；若无合适分类则先建分类目录。
- **不预建空目录**：按需创建，避免结构臃肿。
- **不写死目录名**：索引里的目录名只是「当前快照」，随需求调整并同步索引即可。

### 规则定义方式（各层责任，关键）

两层结构下，「规则写在哪、对谁生效」有显式分工，避免混乱与重复：

| 规则类型 | 定义位置 | 生效范围 | 示例（可替换） |
|----------|----------|----------|----------------|
| 跨域硬规则（与组织结构无关） | 根 `AGENTS.md` §8 通用操作铁律 | 任何任务 / 任何域 | 系统级计划任务逐次授权、密钥红线、脚本 LF 换行 |
| 域专属强制规则 | 该域 `README.md` 的「⚠️ 强制规则」 | **仅本域** | 禁止裸删生产数据 / 改动须本人确认 / 触碰前先读 README |
| 分类级共同注意 | 分类 `README.md`（薄说明） | 该分类（**建议性，非强制**） | 本分类均涉及远端服务，操作前先读对应域 README |
| 跨域约定记忆 | 工作区 `MEMORY.md` | 工作区级 | 文件归属规则、命名规范、操作铁律 |
| 域专属现状/铁律 | 域 `README.md` | 仅本域（不重复进 `MEMORY.md`） | 修复状态、域专属红线 |

> **原则**：强制规则要么进根 `AGENTS.md`（跨域），要么进域 `README.md`（本域），**绝不进分类 `README.md`**；分类 `README.md` 只放建议性说明。

## 4. 归档分类层级

```
L1  根治理文件        AGENTS.md / README.md / PROJECT_INDEX.md
 │
L2  分类目录          顶层目录，按作用域归类（如 infra/ net/ personal/ meta/）；可带薄 README（仅分类级说明）
 │   └─ L3 主题域目录  分类下的子目录，一个主题域一个；内含 README.md（承载本域规则与现状）
 │        ├─ README.md     用途 / 关键文件 / 强制规则 / 状态
 │        ├─ 脚本·文档·配置 域内产出物（*.sh *.py *.ps1 *.md *.yaml …）
 │        └─ （可选）子目录  按子主题再分，如 deploy/1panel/
 │
L4  （可选）域内子主题  用子目录或文件前缀区分，不跨域
```

> **记忆分层**（不在目录树内）：跨域的通用约定（文件归属、命名规范、操作铁律）放工作区级 `MEMORY.md`（WorkBuddy 下位于 `.workbuddy/memory/MEMORY.md`）；域专属的操作铁律与现状一律写在对应域 `README.md`，不在此重复——避免啰嗦与内容漂移。

## 5. 通用组织约定

### 5.1 文件写入流程（先定域，再写）

生成**任何文件**前：

1. **判分类与主题域**：这个产出属于哪个分类下的哪个主题域 / 任务？
2. **定目录**：已有对应主题域 → 放入；无 → 归入某分类（无则先建分类目录）并新建主题域子目录，补 `README.md` + 索引登记。
3. **定命名**：参考 §5.2（建议，非强制）。
4. **写后维护**：更新该域 `README.md` 与 `PROJECT_INDEX.md` 状态。

> 🚫 禁止未经判断直接把文件丢进根目录。

### 5.2 命名规范（建议，可随习惯调整）

| 类型 | 建议格式 | 示例 |
|------|----------|------|
| 文档 | `主题-YYYYMMDD.md` | `网络诊断报告-20260706.md` |
| 脚本 | `功能描述.sh` / `.py` / `.ps1` | `status-check.sh` |
| 配置 | `功能描述.yaml` / `.conf` | `app-config.yaml` |
| 日志 | `YYYYMMDD-主题.log` | `20260706-network.log` |
| 项目子目录 | `YYYY-MM-DD-项目名/` | `2026-04-10-project-migration/` |

### 5.3 会话启动（轻量，省上下文）

1. 读 `AGENTS.md`（必读）。
2. **默认不预载**各主题 `README.md`，避免浪费上下文。
3. 需了解有哪些主题及其状态 → 按需读 `PROJECT_INDEX.md`（轻量地图）。
4. 任务**明确属于某主题域**时，才读该域 `README.md`（其强制规则只在该域生效）。

### 5.4 任务收尾

- 新建/变更主题域 → 更新 `PROJECT_INDEX.md`。
- 域 `README.md` 规则与现状不符 → 同步修正。
- 跨会话需长期记住的偏好/事实 → 写入工作区 `MEMORY.md` 或域 `README.md`。
- 若工作区启用 Git，收尾时增加提交步骤；否则改动即本地生效。

## 7. 记忆维护规则（错误信息去留）

> 本节仅约定**本工作区特有**的记忆内容治理（错误信息去留、分层）；通用记忆机制（存储位置、读写时机、层级划分）以所用 AI 助手的平台记忆系统为准，不在此重复，冲突时以平台为准。

记忆（工作区 `MEMORY.md` 与各域 `README.md` 内的长效说明）随多轮对话累积，须定期清理以保持精简、去重、聚焦。以**手动定期整理**为基线；若所用 AI 助手支持「应用内自动化」之类的能力，可借此辅助蒸馏——属平台特性，非必需。

- **已修复且无价值的错误记录 → 删除**：纯回溯性的「某阻塞/故障已解决」类陈述，一旦修复完成、不再指导未来操作，即移除，避免膨胀与误导。
- **有诊断价值的错误记录 → 保留（可压缩）**：以下类型应保留，因其能指导未来避坑或决策：
  - 可能复发的**根因分析**（环境/配置特性）；
  - 触发过**硬规则边界**的案例；
  - 与外部系统交互的**已知约束与机制**。
- **判断原则**：问自己「三个月后这段还能帮上忙吗？」——不能的删，能的留（尽量压缩成一句话指针，不写长篇回溯）。
- **分层**：跨域约定只在工作区 `MEMORY.md`；域专属铁律/现状只在对应域 `README.md`，不重复。

### 6.4 域 `README.md` 模板（每个主题域复制一份）

```markdown
# <分类>/<域名> — <一句话用途>

> 本文件承载 **<分类>/<域名>** 域的专属规则与现状；处理本域任务时，以下强制规则**优先于通用约定**生效。

## 用途

（本域解决什么问题 / 服务于哪个设备·功能·项目）

## 关键文件

- `<file-a>` —— 说明其作用与权威性（如「权威源」「本地副本」「远端已就位」）
- `<file-b>` —— ……

## ⚠️ 强制规则（仅本域生效）

> 仅写**额外于通用铁律（§8）**的本域规则；已被 §8 覆盖的（计划任务授权、密钥红线、LF 换行等）不必重复。

- （如：禁止裸删生产数据 / 改动须本人确认 / 操作前先备份）
- ……

## 状态

- ✅ / 🔶 / ⏳ ……（当前进度与遗留项，一句话即可）

## 备注

- （可选：与其他域的边界、已知约束、复盘指针）
```

### 6.5 分类 `README.md` 模板（可选，每个分类复制一份）

```markdown
# <分类名>/ — <一句话范围>

本分类涵盖**<一句话说明作用域>**主题（如站点 / 密码后端 / 网络 / 个人文档 / 工作区元）。

- 各子目录为独立**主题域**，域级强制规则见各自 `README.md`，**只在本域生效**。
- 本分类目录**不承载**域强制规则；如需分类级共同注意，写在此文件（薄说明）。
- 新增域 → 在 `PROJECT_INDEX.md` 的 `<分类名>/` 下登记。
```
